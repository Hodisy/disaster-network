# Supporting documents and official event check

Implemented source, 22 October 2026. Allstorm policies and dossier identities remain synthetic. Runtime behaviour has not been validated in this pass: no app launch, build, browser check, database operation, paid OpenAI call or live CatNat lookup was executed. Official API documentation was consulted; the offline sample policy PDF was generated and visually inspected.

## Small complete workflow

1. Unlock the workspace in Settings and verify Jules's policy during a Live call. Save the report, or read the existing reported claim through the verified harness. This issues a separate 30-minute evidence capability for the same browser, alongside the claim read grant.
2. Open My claim. Download the policy PDF, attach existing damage photos or a supporting PDF. Stored files are shown only after PostgreSQL confirms them. Refresh re-reads the dossier's files through the protected endpoint.
3. Choose AI reading explicitly. With that choice selected, Attach and read stores each file first, then sends it to OpenAI for extraction. Without it, files are stored without AI processing. Read document can process a saved file later. A failure to read never removes a successfully stored file.
4. Review the extracted observations/invoice fields, deterministic comparisons and policy clause/page. Every result remains subject to review. No claim stage, coverage, site access, payment, booking or assignment is changed.
5. Check official source queries Géorisques GASPAR for the insured municipality and event date, retaining its URL and actual consultation time. This public lookup is separate from the versioned scenario context.

The client page orchestrates `useClaimEvidence`; `ClaimEvidenceChat` and `DocumentList` receive props and emit events. There is no free-form Live text-chat model in this increment. The document conversation supports attachments, extraction results and the official-source check. Scripted-mode files and messages remain browser-local.

## Storage without a migration

Existing `disaster_demo.documents` stores the attachment bytes, SHA-256, filename, MIME, category, language and `customer_provided` provenance linked exclusively to Jules's existing claim. Uploads accept JPG, PNG and WebP; PDFs are accepted for categories other than photos. Empty files, unsupported signatures, files over 10 MiB and invalid/encrypted PDFs are rejected. PDFs are limited to 12 pages; the dossier is limited to 12 files and 30 MiB in total. Images are signature-checked, not authenticated or forensically validated. Original file metadata can remain in the stored/transmitted bytes.

Identical content/category uploads are idempotent under the existing maintenance lock. Uploads add an `evidence_received` event. Reading adds `evidence_analysis_started`, then `evidence_analysis_completed` or `evidence_analysis_failed`. Completed events hold extracted facts, locale, time, document SHA-256, policy version/hash, claim version token, comparisons and source references. No full binary or verification answer goes into an event or log. Results do not overwrite customer messages or policy sources. The two-minute persisted analysis lease blocks concurrent duplicate reads. A completed matching analysis can be reused without another model request. Changing locale can require another read if requested.

Document deletion and automatic retention cleanup are not included. The explicitly confirmed maintenance reset still removes all data within the marked evaluation schema, including new evidence. A local reset does not delete persisted files. No reset or database update was run for this implementation.

## AI extraction and checks

The server uses the [Responses API file-input protocol](https://developers.openai.com/api/docs/guides/file-inputs) for PDFs and [image inputs](https://developers.openai.com/api/docs/guides/images-vision) for photos, with [structured output](https://developers.openai.com/api/docs/guides/structured-outputs). Private `NUXT_OPENAI_EVIDENCE_MODEL` defaults to `gpt-6-luna`, which documents image input and structured-output support. It uses the existing private OpenAI key. No permanent key reaches the browser. Inputs use inline base64, `store: false`, a 45-second timeout, bounded output and no model tools. No uploaded OpenAI Files object is created. `store: false` is not a claim of zero provider retention.

The model extracts document type, brief observations, uncertainties, explicit invoice total/currency, stay dates/nights, and readable policy/first-name fields. File text is untrusted; embedded instructions are not authority. A photo cannot establish capture date/location, authenticity, causal attribution, loss valuation or eligibility. Unreadable/missing fields remain null. Structured output is bounded and checked again on the server.

The core, not the model, compares policy validity on the reported event date, invoice total against the stored accommodation cap, nights against the policy maximum, average nightly cost against the household nightly limit, dates/nights against the declared request, declared unusability/accommodation need, recipient first name and an explicit policy number when present. Totals are integer cents. A nightly average does not validate every line item or reimbursable charge. A first-name match is not identity verification. Each consistent result describes only that comparison; the overall result always remains `needs_review`, with `coverageConfirmed: false`. Missing information, foreign currency and inconsistent fields require review. Prior analyses are marked stale when policy contents or the claim version changes.

## Official public source

The connector uses [Géorisques GASPAR](https://www.georisques.gouv.fr/donnees/bases-de-donnees/procedures-administratives-relatives-aux-risques), not general web search. The official [API documentation](https://www.georisques.gouv.fr/doc-api) links the OpenAPI definition at `https://www.georisques.gouv.fr/api/v3/api-docs/georisques-api-v1`. The [access page](https://www.georisques.gouv.fr/inscription) states that API v1 remains accessible without a token.

`GET https://www.georisques.gouv.fr/api/v1/gaspar/catnat` uses `code_insee`, `page` and `page_size`. Only the policy's municipality code is transmitted; no customer identity, precise address, photo or invoice goes to Géorisques. The event-period and flood-risk filtering happens on the server using the documented `date_debut_evt`, `date_fin_evt`, `libelle_risque_jo`, `code_insee`, `code_national_catnat` and `date_publication_jo` fields. Queries are bounded to five pages of 100, a shared 15-second deadline and response size checks. Partial pagination cannot become a definitive no-match. The endpoint hostname is fixed; upstream redirects are rejected.

Results are `matching_record_found`, `no_matching_record`, `incomplete` or `unavailable`, with actual consultation time and exact query URLs. The latest same-event result is reused for five minutes. It is persisted as an `official_source_checked` event. GASPAR data can follow Journal officiel publication with a delay; no matching record is not proof of rejection. A matching period/municipality/flood record still needs official-order review and does not validate a property's damage or insurance cover. The independent fictional contractual flood route remains separate. The connector never sets `claims.assessment`, policy CatNat status or coverage approval. There is no news search, general web-search tool or MCP server in this workflow.

## API and authorization

`POST /api/hotline/evidence/{list,upload,download,contract,analyze,source}` -> evidence core -> repository/service. Every action requires the existing enabled/private workspace admission, exact Origin, custom `X-Hotline-Request` header, HttpOnly same-site cookie and unexpired evidence capability. The cookie's existing `/api/hotline` path covers these nested endpoints. The evidence capability is issued only after verified access to a reported dossier; the workspace key alone is insufficient. It survives voice termination but expires after 30 minutes and disappears on server restart. This remains evaluation access control, not production authentication.

Upload uses one multipart `file`, `kind` and optional `locale`; other actions use a bounded JSON body. Analyze requires `documentId` and `consent: true`. Download accepts only a UUID belonging to the reserved dossier; contract ignores arbitrary policy IDs. Downloads use attachment disposition, no-store and nosniff. Browser previews fetch through that same protected API, create local object URLs and release them on navigation. PDFs are sandboxed with a download alternative. Errors expose safe codes only. All database work uses the marked schema, parameterized statements and the same advisory transaction lock as maintenance reset. No lock is held across OpenAI or Géorisques calls.

HTTP requests are limited per direct source IP, with a separate work-action limit. The access state and HTTP limits remain process-local; use the existing single-process evaluation setup. New model account access, SQL execution, actual uploads/downloads, browser PDF behaviour and Géorisques connectivity remain to be checked by the user. No live successful result is claimed from source implementation alone.
